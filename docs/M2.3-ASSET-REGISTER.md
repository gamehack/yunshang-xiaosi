## 1. 冻结原则

- 首个 ULTRA 垂直切片只覆盖现有临水茶室及相邻庭院，不扩建全园。
- 现有 Three.js 世界、导航、碰撞、座椅锚点、访客状态机、存档、音景保持不变。
- 所有新资产先以新版本/候选文件落盘，不覆盖已入库的 `teahouse.blend`、`pavilion.blend` 和现有运行时代码。
- Blender 源文件是权威资产；GLB 是可重建的运行时交付物。没有源文件、导出报告和预览证据的 GLB 不得进入正式运行时目录。
- Blender 中的视觉结果不是最终验收。每项资产必须在 Three.js 实际光照和游戏相机下复核。
- R5 真实硬件验收仍独立保留；不能用 Blender 渲染、SwiftShader 或 Preview 单次 HUD 代替。

## 4. 建议制作顺序

1. A01 茶室 v02：先修正建筑结构阅读和屋面/檐口细节，确保主机位剪影成立。
2. A03 地台/铺地：让建筑与庭院有可信的接地关系，保留可行走面。
3. A04 太湖石 hero cluster：用一个高质量主石建立风格基准，再派生次石。
4. A05 竹丛 hero clump：验证枝叶形态、叶簇密度和镜头近景遮挡。
5. A07 岸线/水生植物：打通建筑、石、植物与水面的自然过渡。
6. A08 水材质和光照：在 Three.js 运行时中校准，不在 Blender 静态预览中单独定稿。
7. A02/A06/A10/A11：根据完整切片的视觉缺口决定是否投入。

## 6. 资产制作规格

- Blender：5.2.4 LTS；米制；1 Blender unit = 1m；Z-up；模型底面 Z=0。
- GLB：glTF 2.0，自包含；相机/灯光由运行时控制；模型正面遵循现有管线约定。
- 材质：Principled BSDF / glTF PBR；Base Color 贴图为 sRGB；Normal/Roughness/AO 为 Non-Color；复杂节点烘焙后再导出。
- 纹理默认 1K/2K；近景 hero asset 可申请 4K，但需记录原因和显存影响。
- 每个资产记录：源文件、导出 GLB、世界/局部尺寸、三角面数、mesh 数、材质数、贴图分辨率/体积、文件大小、LOD 策略、作者/来源/许可。
- 命名：`<category>_<asset>_<variant>_vNN`，如 `architecture_teahouse_main_v02`。
- 源文件和运行时资产分开存储；先入候选目录，验收通过再进入正式运行时加载路径。
- 资产必须在现有角色身高、座面、通行宽度和实际游戏相机下校验，不能只凭 Blender 视口判定比例。

## 7. 首批性能预算（待 R5 实测后校准）

沿用已有茶室切片初始预算，禁止无依据放宽：

- 主机位 draw calls ≤180。
- 可见三角面 ≤90,000。
- 茶室 hero GLB 目标 ≤2 MiB；其余资产按需加载，不把全部资产塞入首屏。
- 首屏关键资产下载目标 ≤16 MiB。
- 中端真实 PC 目标 60 FPS，P95 帧时间目标 ≤16.7ms；必须注明 CPU/GPU、Chrome 版本、视口、DPR、画质、采样时长。
- 优先采用实例化、LOD、合理阴影范围和按需加载；不使用全屏 SSR。
